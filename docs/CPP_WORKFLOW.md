# C++ Build, Run and Debug Workflow

The Emacs DevKit includes an integrated terminal, a bottom compilation panel, and keyboard shortcuts for C++ development on Ubuntu 24.04.

## Recommended layout

- Left: Treemacs project explorer (F8)
- Center: source editor with tabs
- Bottom: persistent terminal (F9), build output, or GDB
- Use Ctrl+P to locate files and Ctrl+Shift+P for Emacs commands.

## Shortcuts

| Shortcut | Action |
| --- | --- |
| Ctrl+F5 | Configure the nearest CMakeLists.txt project for Debug |
| F5 | Build with CMake or compile the current standalone C++ source |
| F6 | Run a previously built executable (select it in the file picker) |
| F7 | Debug a previously built executable with GDB |
| F8 | Toggle Treemacs |
| F9 | Open/focus a terminal in the bottom panel |
| F10 | Docker integration |
| F12 | Go to symbol definition |
| Ctrl+C, then F | Format a C++ buffer with clang-format |

F5 starts a build. It does **not** automatically run or debug the result. Compilation, running, and debugging are separate steps to keep them predictable.

## Standalone C++ source

```bash
mkdir -p ~/Projects/cpp-example
cat > ~/Projects/cpp-example/main.cpp <<'CPP'
#include <iostream>
int main() {
    std::cout << "Hello from Emacs DevKit\n";
    return 0;
}
CPP
emacs ~/Projects/cpp-example/main.cpp
```

Within Emacs, press F5. The build uses g++ with `-std=c++20 -Wall -Wextra -g -O0`, producing `build/main` relative to the source directory. Use F6 and select `build/main` to run it. Use F7 and select the same binary to debug.

The single-file build is appropriate for one standalone source file. Multiple translation units require a build system such as CMake.

## CMake workflow

Project example:

```text
my-project/
├── CMakeLists.txt
├── include/
├── src/
│   └── main.cpp
└── build/          # Generated by CMake
```

Example `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyProject LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(my_app src/main.cpp)
target_compile_options(my_app PRIVATE -Wall -Wextra -Wpedantic)
```

Open a C++ file in the project and press Ctrl+F5 for the configuration step, then F5 to build. Configuration defaults to Debug mode and exports `compile_commands.json`, so clangd can understand compile flags.

The setup uses Ninja when available, falling back to Unix Makefiles if Ninja is missing. Existing CMake build caches retain their selected generator. CMake projects may produce multiple executables, so F6 and F7 ask you which binary to use. For a target named `my_app`, select `build/my_app`.

If clangd cannot find the compilation database, create a project-root link:

```bash
ln -sfn build/compile_commands.json compile_commands.json
```

Avoid mixing build directories that were configured by different generators.

## Debugging with GDB

Build in Debug mode first. Press F7, select your executable, then use the Emacs GDB interface. Common GDB commands:

```text
break main
run
next
step
continue
print my_variable
backtrace
```

The default Emacs GDB interface supports source browsing, breakpoints, stack frames, and variable inspection. F7 needs `gdb` installed and an executable with debug information.

## Terminal panel

F9 opens or focuses `*DevKit Terminal*` in a lower window. It prefers `vterm` and falls back to the built-in `shell` if vterm is unavailable. The terminal remains interactive for programs using `std::cin`, unlike the compilation buffer.

For interactive applications:

```bash
./build/main
```

## Troubleshooting

- Build fails: read `*compilation*`; press Enter on errors to jump to source locations.
- Cannot configure: confirm `CMakeLists.txt` exists in the project and CMake is installed.
- Executable not found: run F5 first, then choose the actual executable in the build directory.
- No symbols in GDB: configure a Debug build; ensure compilation uses `-g`.
- vterm compilation fails: use `M-x shell`; check `libvterm-dev`, CMake and a compiler.
- Existing key bindings differ: run `M-x describe-key` to inspect them.
- Existing manually customized Emacs: read the update and rollback sections of [the user guide](USER_GUIDE.md).

This workflow targets native Linux development. Cross-compilation, Yocto toolchains, remote debugging, and complex CMake Presets need project-specific configuration.
